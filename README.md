# twitch.lua — плагин Twitch для VLC

**Русский** | [English](README_ENG.md)

Скрипт плейлиста для VLC, который открывает прямые трансляции и записи (VOD) Twitch прямо в VLC.

Он заменяет стандартный `twitch.lua`, поставляемый с VLC 3.0. Стандартный скрипт обращается к удалённым эндпоинтам `api.twitch.tv/api/*` и Kraken, а они теперь отвечают HTTP 410. Эта версия повторяет схему веб-плеера Twitch: сначала GQL-запрос `PlaybackAccessToken`, затем мастер-плейлист HLS с `usher.ttvnw.net`.

## Возможности

- Воспроизводит трансляции и VOD анонимно. Вход в аккаунт, OAuth-токен и Client-Integrity не нужны.
- Делает один GQL-запрос на открытие: он возвращает сразу и токен доступа, и метаданные (название, имя канала, категорию, статус трансляции).
- Заполняет метаданные VLC: *Название*, *Исполнитель*, *Жанр*, *Сейчас играет* и *Описание*.
- Пишет понятные ошибки в журнал VLC, если канал не найден, трансляция не идёт или токен отклонён (например, из-за геоблокировки).
- Сразу стартует на лучшем качестве. Скрипт пропускает вариант только со звуком и использует `adaptive-logic=highest`, поэтому нет разгона с 160p, перезапуска демуксера и пересинхронизации PCR после старта.
- **Обрабатывает серверный преролл.** Без этого VLC 3 показывает чёрный экран без звука после рекламы. Скрипт проигрывает рекламу отдельным элементом и затем переключается на эфир за точкой разрыва (подробнее — в разделе [Реклама перед трансляцией](#реклама-перед-трансляцией)).
- Работает на Windows, Linux и macOS.

## Поддерживаемые ссылки

| Ссылка | Что открывается |
|---|---|
| `https://www.twitch.tv/<канал>` | Трансляция |
| `https://twitch.tv/<канал>` | Трансляция |
| `https://m.twitch.tv/<канал>` | Трансляция |
| `https://go.twitch.tv/<канал>` | Трансляция |
| `https://www.twitch.tv/videos/<id>` | VOD |

Клипы (`clips.twitch.tv`) не поддерживаются и намеренно не распознаются.

## Требования

- VLC 3.0.x.
- `curl` в `PATH`. Lua API VLC умеет отправлять только GET-запросы и без своих заголовков, поэтому GQL-запрос методом POST уходит через системный `curl`. Плейлисты (в том числе при ожидании эфира после рекламы) загружаются средствами самого VLC, без внешних процессов.

| ОС | curl |
|---|---|
| Windows 10 1803+ / 11 | Встроен (`C:\Windows\System32\curl.exe`) |
| macOS | Встроен (`/usr/bin/curl`) |
| Linux (пакет дистрибутива) | Обычно уже установлен. Если нет — `sudo apt install curl` или аналог для вашего дистрибутива |
| Linux (Flatpak / Snap) | VLC использует curl из своей песочницы, а там его может не быть. См. [Диагностику](#диагностика) |

## Установка

Скопируйте `twitch.lua` в пользовательскую папку скриптов плейлиста, создав её при необходимости:

| ОС | Путь |
|---|---|
| Windows | `%APPDATA%\vlc\lua\playlist\` |
| Linux | `~/.local/share/vlc/lua/playlist/` |
| Linux (Flatpak) | `~/.var/app/org.videolan.VLC/data/vlc/lua/playlist/` |
| Linux (Snap) | `~/snap/vlc/current/.local/share/vlc/lua/playlist/` |
| macOS | `~/Library/Application Support/org.videolan.vlc/lua/playlist/` |

VLC загружает пользовательские скрипты раньше встроенных, поэтому этот файл автоматически заменяет встроенный `twitch.luac`. После установки перезапустите VLC.

## Использование

- **Интерфейс:** *Медиа → Открыть URL* (`Ctrl+N`), вставьте ссылку на канал или VOD.
- **Командная строка:**
  ```sh
  vlc https://www.twitch.tv/<канал>
  vlc https://www.twitch.tv/videos/<id>
  ```

## Настройка

Все параметры задаются константами в начале скрипта.

### Качество

```lua
local OPTIONS    = { ":adaptive-logic=highest" }
local MAX_HEIGHT = 0
```

`OPTIONS` действует, когда VLC получает мастер-плейлист (обычный запуск без рекламы и VOD):

| Значение | Поведение |
|---|---|
| `:adaptive-logic=highest` | По умолчанию. Лучший вариант с первого сегмента, качество никогда не снижается |
| `:adaptive-logic=nearoptimal` | Подстраивается под скорость канала. Лучше для нестабильного интернета, но может стартовать с более низкого качества |
| `:adaptive-logic=highest`, `:adaptive-maxheight=720` | Лучший вариант, но не выше 720p |

`MAX_HEIGHT` действует, когда сработал обход преролла. В этом случае VLC получает один media-плейлист конкретного качества, и переключаться ему не на что. Скрипт сам выбирает вариант с наибольшим разрешением (при равенстве — с большим FPS, затем с большим битрейтом), но не выше `MAX_HEIGHT`. `0` означает лучшее доступное. Порядок вариантов в мастер-плейлисте Twitch не используется: он бывает разным.

Эти параметры действуют только на элементы, созданные скриптом. Глобальные настройки VLC не меняются.

### Реклама перед трансляцией

```lua
local SKIP_PREROLL  = true
local LIVE_DELAY_MS = 4000
local LIVE_MARGIN_S = 1
local AD_CUT_S      = 1
local RESUME_MAX_S  = 30
local PREROLL_MAX_S = 90
```

| Константа | Назначение |
|---|---|
| `SKIP_PREROLL` | `false` отключает обработку рекламы, скрипт ведёт себя как раньше |
| `LIVE_DELAY_MS` | Желаемая задержка от края эфира после рекламы (`:adaptive-livedelay`) |
| `LIVE_MARGIN_S` | Запас живого контента сверх расчётного порога перед переключением |
| `AD_CUT_S` | На сколько секунд раньше конца остановить рекламный элемент. Если в конце рекламы мелькает чёрный кадр, увеличьте до `2` |
| `RESUME_MAX_S` | Максимальное ожидание эфира после рекламы |
| `PREROLL_MAX_S` | Максимальное ожидание, если длина рекламы неизвестна |

## Как это работает

1. `probe()` проверяет, что ссылка ведёт на twitch.tv.
2. `parse()` извлекает из ссылки логин канала или id VOD.
3. `gql()` отправляет через `curl` один POST на `https://gql.twitch.tv/gql` с публичным веб-`Client-ID`. Запрашивается:
   - для трансляции: `streamPlaybackAccessToken` и `user { displayName stream broadcastSettings }`;
   - для VOD: `videoPlaybackAccessToken` и `video { title description owner game }`.
4. Скрипт собирает URL usher из `value` и `signature` токена:
   - трансляция: `https://usher.ttvnw.net/api/channel/hls/<login>.m3u8?...`
   - VOD: `https://usher.ttvnw.net/vod/<id>.m3u8?...`
5. Для трансляции скрипт загружает мастер-плейлист и media-плейлист выбранного варианта и проверяет, есть ли в начале сессии вставленная реклама (метки `DATERANGE` класса `twitch-stitched-ad` и названия сегментов).
6. Если рекламы нет, возвращается элемент плейлиста с метаданными, и дальше HLS-поток воспроизводит демуксер `adaptive` VLC. Если реклама есть — см. ниже.

В теле запроса нет строковых литералов, обратных слэшей и переводов строк: все значения передаются как переменные GraphQL. Поэтому одна функция экранирования безопасно работает и для `cmd.exe`, и для `sh`, без временных файлов.

### Обход преролла

У анонимных токенов `server_ads: true`, и Twitch вставляет рекламу прямо в HLS-поток. Переход с рекламы на эфир отмечен `EXT-X-DISCONTINUITY` с большим скачком временных меток. VLC 3 теряет на нём опорные часы: в журнале появляется `Timestamp conversion failed … no reference clock`, на экране чёрный кадр, звука нет.

Скрипт обходит это так:

1. Возвращает **два элемента** плейлиста вместо одного:
   - `[ad]` — media-плейлист сессии с первого сегмента, с `:run-time`, который останавливает воспроизведение за `AD_CUT_S` секунд до разрыва. Реклама честно показывается на экране;
   - служебную ссылку `https://www.twitch.tv/<канал>?vlcresume=…`, которая снова попадает в этот же скрипт.
2. Когда реклама заканчивается, VLC переходит ко второму элементу. Скрипт опрашивает плейлист, пока в его конце не наберётся достаточно живых сегментов.
3. Затем он открывает ту же сессию у края эфира, уже за точкой разрыва.

Порог ожидания считается от реальной длины сегмента, а не от `#EXT-X-TARGETDURATION`. VLC 3 никогда не стартует ближе трёх сегментов к краю эфира, а у Twitch `TARGETDURATION` равен 6 при сегментах по 2 с. Расчёт по `TARGETDURATION` давал лишние ~15 с ожидания.

Если длина рекламы неизвестна (в `DATERANGE` нет `DURATION`), скрипт не показывает рекламу, а молча ждёт эфир до `PREROLL_MAX_S` секунд. Если какой-то плейлист не удалось прочитать, скрипт откатывается к обычному поведению с одним элементом.

## Диагностика

Откройте *Инструменты → Сообщения* в VLC или запустите `vlc -vv` и найдите строки, начинающиеся с `Twitch:`.

| Сообщение в журнале | Что значит / что делать |
|---|---|
| `bad GQL response: empty (is curl installed?)` | `curl` не найден или ничего не вернул. Установите curl или проверьте, что он есть в `PATH` |
| `GQL error: ...` | Twitch отклонил запрос. Возможно, изменился API — создайте issue |
| `channel not found: <name>` | Логин написан с ошибкой, либо канал забанен или удалён |
| `<name> is offline` | Канал сейчас не ведёт трансляцию |
| `playback forbidden: <code>` | В токене отказано, например из-за геоблокировки |
| `no access token for video <id>` | VOD не существует или не публичный |
| `server-side preroll (Ns announced), playing it first` | Обнаружена реклама, она показывается отдельным элементом |
| `server-side preroll of unknown length, waiting for live` | Длина рекламы неизвестна, скрипт ждёт эфир без показа рекламы |
| `preroll done, switching to live` | Реклама закончилась, скрипт ждёт живые сегменты |
| `live content ready after N poll(s), Ns` | Эфир готов, VLC открывает его (уровень debug) |
| `variant <N>p chosen` | Какое качество выбрано для обхода преролла (уровень debug) |
| `live wait timed out, playback may stall at the ad boundary` | Эфир не появился за отведённое время. Возможен чёрный экран — откройте ссылку заново |
| `master playlist unreadable, preroll not handled` / `media playlist unreadable, preroll not handled` | Плейлист не загрузился, скрипт работает как без обхода рекламы |

**Flatpak / Snap:** проверьте, виден ли curl внутри песочницы:

```sh
flatpak run --command=sh org.videolan.VLC -c 'command -v curl'
snap run --shell vlc -c 'command -v curl'
```

Если команда ничего не вывела, используйте VLC из пакета дистрибутива.

## Известные ограничения

- **Мелькание консоли на Windows.** `io.popen` запускает `cmd.exe`, поэтому при каждом открытии ссылки Twitch на мгновение появляется окно консоли. Это ограничение Lua-песочницы VLC. Ожидание эфира после рекламы консоль не открывает.
- **Загрузка HTML до запуска скрипта.** VLC скачивает HTML-страницу twitch.tv (~200 КБ) ещё до вызова `probe()`. Скрипты плейлиста работают как фильтры потока поверх уже открытого URL, поэтому этого не избежать.
- **Пауза после рекламы.** Между концом рекламы и началом эфира проходит около 5–6 с тёмного экрана: VLC 3 не умеет стартовать ближе трёх сегментов к краю эфира.
- **Два элемента в плейлисте.** Во время рекламы в плейлисте VLC видны `[ad]` и служебная ссылка `?vlcresume=…`.
- **Несколько рекламных роликов подряд.** На экране показывается только первый ролик, остальное время скрипт ждёт эфир на тёмном экране.
- **Реклама посреди трансляции (мидроллы)** не обрабатывается и может вызвать чёрный экран или зависание.
- **Контент только для подписчиков.** Такие VOD и трансляции требуют авторизованного токена, который скрипт не поддерживает.
